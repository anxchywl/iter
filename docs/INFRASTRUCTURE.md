# Local development, checks, and deployment

The backend is in `backend/` and uses Python 3.12+, `uv`, FastAPI, PostgreSQL, and Alembic. Set `DATABASE_URL` to a PostgreSQL psycopg URL and `ADMIN_CREDENTIALS_JSON` to a JSON object mapping operator IDs to distinct secrets of at least 32 characters. The application does not create schema at startup: run `cd backend && uv run alembic upgrade head` with `DATABASE_URL` set, then start `uv run uvicorn app.main:create_app --factory`. Keep credentials outside the repository and expose the admin API only through an HTTPS access path appropriate for operators.

The website is in `frontend/` and uses Node 22+, the checked-in npm lockfile, and Next.js. Run `npm ci`, then `DIRECTORY_API_URL=http://127.0.0.1:8000 npm run dev`. The API URL is server-only. Same-origin `/api/feedback/reviews` and `/api/feedback/reports` forward bounded JSON to the backend; use a trusted proxy and shared client-aware rate limit before opening public submissions beyond one local backend process. Configure `TELEGRAM_BOT_USERNAME` and optional `TELEGRAM_APP_SHORT_NAME` only after the corresponding Mini App points at this same website; without them the Telegram launch link is hidden. A [Telegram direct link](https://core.telegram.org/bots/webapps#direct-link-mini-apps) uses `startapp=job_<listing UUID>` and the site resolves `tgWebAppStartParam` to its normal detail route. `DIRECTORY_DEMO_MODE=true` visibly labels local fixture data; never enable it for a public release. No bot token belongs in the frontend.

Use separate development, test, and production databases and configuration. Keep secrets out of the repository and client bundles. Test data may contain clearly marked fictional jobs; production import must reject fixture markers and must not fall back to fixtures after a data or configuration failure. Never use real student data in tests or screenshots.

Backend checks from `backend/` are `uv run ruff check app tests alembic/env.py` plus any new migration, `uv run ruff format --check app tests alembic/env.py` plus any new migration, and `POSTGRES_TEST_URL=<isolated PostgreSQL URL> uv run pytest -q`. The integration tests apply Alembic migrations to that test database and truncate test records; never point them at a real database. Frontend checks from `frontend/` are `npm run format:check`, `npm run typecheck`, `npm test`, `npm run test:e2e`, and `npm run build`. Browser checks use a clearly marked local fixture; a real Telegram client launch remains unverified until a bot and HTTPS site are configured. CI and a deployment target do not exist yet.

Schema changes require versioned migrations tested from the previous schema with representative data, plus a restore rehearsal. Back up the database before migration or deployment and verify restoration. A release preflight must refuse missing production configuration, development credentials, fixture data, and absent persistence/backup. CI validates changes; deployment requires a separate authorized task.
